# Owner-Autonomous Engineering: Zero-Approval PRs and Honest Milestone Sync

**Effective owner instruction: 23 November 2026.** An authorized engineering autopilot may perform the whole ordinary bounded PR lifecycle, including source changes, tests, CI repair, reviews as **agent self-review**, docs generation, and safe eligible merge. **No mandatory independent human approving review.** GitHub branch ruleset sets `required_approving_review_count: 0`. Never make a fake APPROVED review, conflate an agent's own comment with independent verification, or evade security/CI checks. This supersedes older independent-human-review requirements on routine work. The seven-level/CISSP/SRE/management/CA/MBA perspectives are technical review lenses, not separate certified reviewers.

## Main ruleset — manual import required

Import [`.github/rulesets/autopilot-main-no-human-review.json`](../../.github/rulesets/autopilot-main-no-human-review.json) through GitHub **Settings > Rules > Rulesets**. The JSON only protects main **after the administrator imports/enables it**. Scope: required PR, zero approval count, resolved threads, strict updated base/checks, block branch deletion and force push, no configured bypass. Check names are drawn from unconditional PR jobs: `Milestone documentation sync`, `Rust core`, `Nuxt frontend`, `Production JavaScript dependency audit`, `Rust dependency audit`. Do not require optional/path-filtered cross-browser jobs on every docs PR; do run them when changed scope triggers the workflow. If import is unsupported or check names do not match, report the settings blocker instead of misrepresenting protection.

## Bounded autonomy loop

1. Read live GitHub first: main SHA, PRs, issues, exact head/base SHAs, workflow jobs and security checks, reviews/threads, branch rules and current source-of-truth record. A dated PR_OPEN in the board must never override a GitHub MERGED state.
2. Prefer an existing eligible PR. Implement the smallest real Nuxt/Vue/TypeScript or Rust/WASM source/test correction, preserving editor defaults, schema v1–v5 migrations, portable JSON, history/autosave, browser-local privacy, PNG and print, and the five-opened-PR budget per feature ID. Only introduce schema v6 when the actual foreground-image contract and parity justify it.
3. Self-review the full diff, inspect negative tests, accessibility/export implications, dependency/supply-chain security, rollback, data integrity and CI. Record an honest comment; do not cast GitHub self-approval as independent review.
4. Merge only after all *configured required* exact-head checks and applicable security checks pass, branch is current with main, no blocking unresolved threads or review requests, ruleset permits merge, and the change is within preauthorized non-release, non-destructive boundaries. Use `expected_head_sha` and verify main postmerge; failing, skipped or absent required checks block. Do not bypass protections or manually alter checks to force green.
5. Reconcile the source-of-truth `docs/engineering/milestone-record.json` with real GitHub merges and **generate all seven protected documentation sections using `scripts/sync-milestone-docs.mjs`** in the same meaningful PR; verify `--check` and generator tests. After a merge, capture actual merge SHA, integrated CI and any defect. A bounded factual reconciliation PR is allowed if leaving the selector factually wrong would misdirect the next run, not for cosmetic timestamps. Do not hand-edit generated markers.
6. A scheduled task may fail, skip or be delayed; the git repository is not an always-on agent. Every run reports CODE CHANGED / NO CODE CHANGED, exact head/main SHA, PR, local checks actually executed, CI conclusions, docs changes, residual blockers, and one next executable job.
